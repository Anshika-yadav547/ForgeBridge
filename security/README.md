# Security Scan — ForgeBridge / AUTOFACTORY-2005

## Purpose

This folder contains the static-analysis security scan for the legacy C source
code in `legacy/AUTOFACTORY-2005/src/`. It is part of Member 4's security
deliverable on the `security-migration` branch.

## Scan target

```
legacy/AUTOFACTORY-2005/src/
```

The six C source files examined are:

- `alarm.c` — safety-interlock evaluation logic
- `diagnostics.c` — diagnostic output
- `main.c` — entry point and hard-coded sensor fixture
- `production.c` — production-enable guard
- `sensor.c` — raw sensor scaling
- `temperature.c` — temperature threshold comparison

> **COBOL is not in scope for Semgrep.**
> `legacy/AUTOFACTORY-2005/cobol/MACHINE-STATUS.cbl` was not scanned by
> Semgrep. The COBOL source is a separate fictional representation of the same
> safety logic and requires a different analysis path.

## Tool

[Semgrep](https://semgrep.dev/) — open-source static analysis.

Rule set: `p/c` (Semgrep's published C ruleset).

## How to run

From the repository root on Windows (PowerShell):

```powershell
.\security\run_scan.ps1
```

Prerequisites:

- Semgrep must be installed and on the `PATH`.
  Install via `pip install semgrep` or from <https://semgrep.dev/docs/getting-started/>.

The script will write results to `security/semgrep-results.json` and exit with
Semgrep's own exit code (0 = no findings, 1 = findings present, 2 = error).

## Results

`security/semgrep-results.json` is generated by the scanner. It contains only
raw Semgrep output and is never manually authored or edited.

## IMPORTANT — scanner output vs. AI explanation

| Layer | What it is | How to trust it |
|---|---|---|
| `semgrep-results.json` | Raw scanner output | Deterministic; cite rule ID, file path, and line number |
| Any written analysis | Human or AI interpretation of findings | Must cite exact file path + line; label as interpretation |

**Scanner findings and AI-generated explanations must always be kept
separate.** Do not present an AI summary of findings as if it were a scanner
result. Every claim about a vulnerability must be traceable to a specific rule
ID and source line in `semgrep-results.json`.

## Project constraints

- Do not bypass legacy safety interlocks (`alarm.c`). See `CHANGE-241.txt`.
- Do not modify legacy C source files as part of the scan.
- Do not commit secrets, API keys, or private keys.
- AUTOFACTORY-2005 is fictional demonstration data; do not treat findings as
  real-world evidence.
